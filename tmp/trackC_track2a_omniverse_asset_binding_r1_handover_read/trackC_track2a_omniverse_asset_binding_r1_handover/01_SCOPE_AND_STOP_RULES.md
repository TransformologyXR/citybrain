# 01 — Scope and Stop Rules

## In scope

- stable asset binding registry
- binding records for BARC/NYC assets
- DATA_FIRST placeholder binding records for cross-city references
- USD prim/path validation
- sidecar marker validation
- confidence and review state
- evidence/limitation binding map
- source-ID boundary labels
- Kit/Composer handoff packets
- stage/camera/bookmark records
- operator/executive handoff notes
- dependency registers

## Out of scope

- event overlay integration
- R7 relationship overlay integration
- live event fabric integration
- source USD mutation
- Composer control automation unless actually implemented
- production Omniverse runtime
- full citywide twin claim

## Stop rules

If event state is required, record:

`DEPENDENCY_EVENT_FABRIC_R2_STATE_MATERIALIZATION_REQUIRED`

If R7 relationship edges are required, record:

`DEPENDENCY_R7_R2_SOURCE_DIVERSITY_REQUIRED`

If product-surface changes are needed, record:

`DEPENDENCY_D6_R3_RELATIONSHIP_OR_EVENT_OVERLAY_INTEGRATION_REQUIRED`

Do not implement those dependencies here.


## Permanent boundaries

Do not claim:
- production readiness
- public deployment
- certified citywide digital twin
- source ID ownership/legal/certified truth
- certified affected-building truth
- confirmed violation
- legal finding
- permit approval/rejection
- certified impact
- certified traffic model
- dispatch/enforcement/routing/control
- autonomous monitoring/alerts
- observed truth from simulation/synthetic
- external LLM as truth engine

Do not mutate:
- Track 1/R5/R6 roots
- Track 2A roots
- Track 2B roots
- Track 2C roots
- D6 R1 roots
- source USD/USDAs
- BARC/NYC 3D export roots
- app source roots
- city source data roots

All writes must remain under the new output root for this task.
